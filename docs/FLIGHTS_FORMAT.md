# פורמט ייבוא טיסות: `latisa-flights` (גרסה 1)

קובץ JSON שמייבאים במסך "טיסות ומעברים", בכפתור "ייבוא טיסות". הקוד: `src/js/core/flights.js`. הבדיקות: `tests/stage9-flights.test.js`.

```json
{
  "format": "latisa-flights",
  "version": 1,
  "flights": [
    { "flightNo": "ZZ 101", "from": "עיר א", "to": "עיר ב", "date": "2030-03-01", "time": "08:00",
      "status": "paid", "ticket": "roundtrip", "price": "3000", "currency": "ILS",
      "seat": "1A", "seatPrice": "90", "company": "", "booking": "", "link": "", "note": "" },
    { "flightNo": "ZZ 102", "from": "עיר ב", "to": "עיר א", "date": "2030-04-01", "status": "paid", "ticket": "included" }
  ]
}
```

הנתונים בדוגמה מומצאים (כלל 16).

## שדות
| שדה | חובה | הערה |
|---|---|---|
| `flightNo` | כן | שתי אותיות או ספרות, ואחריהן 1 עד 4 ספרות ואות אופציונלית. נשמר באותיות גדולות |
| `from`, `to` | כן | עד 60 תווים |
| `date` | כן | `YYYY-MM-DD` |
| `time` | לא | `HH:MM` |
| `status` | לא | `planned` (ברירת מחדל), `booked`, `paid` |
| `ticket` | לא | `oneway` (ברירת מחדל), `roundtrip` (המחיר של כל הכרטיס כאן), `included` (חזור של כרטיס הלוך ושוב, בלי מחיר) |
| `price` | לא | נכנס לתקציב כהוצאה אחת בקטגוריה "טיסה". אסור עם `included` |
| `currency` | לא | מטבע מהרשימה של האפליקציה. ברירת מחדל: הראשון ברשימה (₪) |
| `seat`, `seatPrice` | לא | נשמרים בפרטי הטיסה בלבד. **תשלום על מושב לא נכנס לתקציב** |
| `company`, `booking`, `link`, `note` | לא | כמו בטופס |

## כללי הייבוא
- **כפילות = אותו מספר טיסה ואותו תאריך**, בלי הבדל בין אותיות גדולות וקטנות ורווחים. כפילות מול טיסה קיימת (גם אחת שהוזנה ביד) או מול שורה קודמת באותו קובץ מדלגים עליה. **שום רשומה קיימת לא נדרסת ולא מתעדכנת.**
- שורה לא תקינה מדלגים עליה, עם סיבה. השאר נכנסות.
- לפני הייבוא מוצג סיכום: כמה חדשות, כמה כבר קיימות וכמה לא תקינות. שום דבר לא נשמר לפני "לייבא".
- ייבוא חוזר של אותו קובץ לא משנה כלום.
- רק `transfers` ו-`expenses` של הטיול הפעיל משתנים, ורק בהוספה. מסלול, תקציב, רשימות, צ'ק-אין ותמונות לא נוגעים.
- גרסה גבוהה מ-1: "הקובץ נוצר בגרסה חדשה יותר". פורמט אחר: "זה לא קובץ טיסות".
