## מטרת השלב

- מה עוד לארוז?

בבית מופיע כרטיס קצר עם התשובות. שום כלל או מספר לא מוצג כעובדה.

## מבנה הנתונים (גרסה 3)
**פריט צ'ק ליסט** (`trip.checklist[i]`):
```
{ id, group, name, qty, note, done, verify? }
```
- `group`: אחד מ-`documents`, `money`, `comms`, `health`, `clothing` או `chargers`.
- **הכנות:** מסמכים, כסף ותשלום, תקשורת.
- **אריזה:** בריאות ותרופות, ביגוד ומזוודה, מטענים ומתאמים.
- `verify`: רק לפריטים שתלויים בכללים, כמו תוקף דרכון, אשרה, דרישות כניסה ורישיון נהיגה בינלאומי. המבנה: `{ source, checkedAt }`. כל עוד `checkedAt` ריק, הפריט מסומן "לבדוק".

**משימה** (`trip.tasks[i]`, שדה חדש):
```
{ id, title, status, due, note }
```
- `status`: `open`, `doing` או `done`.
- `due`: `"YYYY-MM-DD"` או `null`.

**המרה מ-2 ל-3:** מוסיפים `tasks: []`. פריטים קיימים ב-`checklist` מקבלים ערכי ברירת מחדל: כמות 1, הערה ריקה, `done: false`. שום נתון אחר לא משתנה.

## הגדרות
- **פס התקדמות:**
  - פס ההכנות = כמה פריטי הכנות מסומנים, מתוך כל פריטי ההכנות. פס האריזה מחושב באותה דרך.
  - כשאין פריטים בכלל מוצג "עוד אין פריטים" ולא 0%.
  - האחוז מעוגל כלפי מטה, כך ש-100% מופיע רק כשהכול מסומן.
- **משימה באיחור:** יש לה תאריך יעד, התאריך מוקדם מהיום לפי שעון בנגקוק, והסטטוס שלה לא "בוצע". מסומנת באדום כהה ועדין, כמו חריגה בשלב 4.
- **המשימה הקרובה:** המשימה הפתוחה (לא "בוצע") עם תאריך היעד המוקדם ביותר. אם לאף משימה אין תאריך, הראשונה ברשימה.
- **הרשימה והמשימות ההתחלתיות:** נמצאות ב-`data/packs/th.js`, כשמות בלבד, בלי כללים, מספרים, תאריכים או שמות תרופות. כל אחת נטענת בנפרד, רק אחרי "כן" ורק כשהרשימה שלה ריקה. הכפתור ננעל בזמן השמירה, ולכן לחיצה כפולה לא מכפילה.
