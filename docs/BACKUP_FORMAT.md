# פורמט קובץ הגיבוי של TISA (חוזה)

קובץ גיבוי שנוצר בגרסה הזו חייב להיכנס גם לכל גרסה עתידית (BETA ומעלה). אסור לשנות שדה קיים בלי פונקציית המרה ב-`src/js/core/schema.js`.

## שם הקובץ
`tisa-backup-YYYY-MM-DD.json`. התאריך הוא יום הייצוא לפי UTC.

## מבנה
```json
{
  "format": "tisa-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-11-19T16:07:00.000Z",
  "data": { "...": "the full app state, see below" }
}
```

| שדה | סוג | חובה | משמעות |
|-----|-----|------|--------|
| `format` | מחרוזת | כן | תמיד `"tisa-backup"`. קובץ עם ערך אחר נדחה |
| `schemaVersion` | מספר שלם | כן | גרסת מבנה הנתונים בזמן הייצוא |
| `exportedAt` | מחרוזת ISO 8601 | כן | זמן הייצוא |
| `data` | אובייקט | כן | כל הנתונים, באותו מבנה שנשמר ב-`localStorage` במפתח `tisa:v1` |

## `data` (גרסה 1)
| שדה | סוג | הערות |
|-----|-----|-------|
| `schemaVersion` | `1` | |
| `appVersion` | מחרוזת | למשל `"0.2.0"` |
| `createdAt`, `updatedAt` | ISO 8601 | |
| `settings.language` | מחרוזת | `"he"` |
| `settings.theme` | `null`, `"light"` או `"dark"` | `null` אומר שהערכה נקבעת לפי המכשיר |
| `settings.lastBackupAt` | ISO 8601 או `null` | |
| `settings.assistantQuestionLimit` | מספר שלם | ברירת מחדל 50 |
| `activeTripId` | מחרוזת | חייב להיות מפתח ב-`trips` |
| `trips` | אובייקט לפי מזהה | |

### טיול (`trips[id]`)
| שדה | סוג | הערות |
|-----|-----|-------|
| `id` | מחרוזת | זהה למפתח. נוצר עם `crypto.randomUUID` |
| `countryCode` | מחרוזת | `"TH"` |
| `name` | מחרוזת | |
| `startDate`, `endDate` | `"YYYY-MM-DD"` או `null` | תאריכים לפי לוח השנה, בלי שעה |
| `destinations` | מערך | תחנות המסלול (שלב 3). ראו למטה |
| `expenses` | מערך | הוצאות (שלב 4). ראו למטה |
| `budget` | אובייקט | משלב 4 (גרסת נתונים 2). ראו למטה |
| `rates` | אובייקט | שערים שהמשתמש ערך, למשל `{ "ILS_THB": 12 }`. ריק = שערי התכנון מחבילת המדינה |
| `transfers` | מערך | שלב 5 |
| `checklist` | מערך | שלב 5 |
| `events` | מערך | שלב 6 |
| `info` | אובייקט | שלב 7 |
| `assistant` | אובייקט | שלב 7 |

שדות שהגרסה הנוכחית לא מכירה נשמרים כמו שהם ולא נמחקים.

### תחנה (`destinations[i]`, משלב 3, גרסת אפליקציה 0.3.0)
| שדה | סוג | הערות |
|-----|-----|-------|
| `id` | מחרוזת | מזהה ייחודי |
| `name` | מחרוזת | עד 60 תווים |
| `startDate`, `endDate` | `"YYYY-MM-DD"` | הגעה ועזיבה. העזיבה לא לפני ההגעה. הלילות = ההפרש בימים, ולא נשמרים |
| `note` | מחרוזת | עד 140 תווים. יכול להיות ריק |
| `flexible`, `nightsRange` | בוליאני, `[מינימום, מקסימום]` | אופציונלי. רק ליעד הגמיש מהמסלול המוצע |

אין שינוי בגרסת הנתונים (`schemaVersion` נשאר 1): השדה כבר היה במבנה כמערך ריק. תחנה שלא אפשר להציג (למשל תאריכים שבורים) נשארת בנתונים ולא נמחקת. המסך פשוט לא מציג אותה.

## כללי ייבוא
1. הקובץ חייב להיות JSON, ו-`format` חייב להיות `"tisa-backup"`. חייבים להופיע בו `schemaVersion`, `exportedAt` ו-`data`.
2. אם `schemaVersion` גבוה מזה של האפליקציה, הקובץ נדחה ומוצגת הודעה לעדכן את האפליקציה.
3. גרסה ישנה יותר עוברת המרה (`migrate`), ואחר כך בדיקת מבנה (`validateState`).
4. לפני שמחליפים את הנתונים מוצג תקציר: שם הטיול, התאריכים ומועד העדכון האחרון. ההחלפה קורית רק אחרי אישור מפורש.
5. כל שגיאה מחזירה קוד ולא משנה את הנתונים: `empty`, `notJson`, `format`, `structure`, `future`.

## היסטוריית גרסאות
- **0 (שלב 1):** המפתחות `tisa:trip` (`{ v: 1, trip: { dates, budget } }`) ו-`tisa:theme`. ההמרה ל-1 מעבירה את התאריכים ל-`startDate` ו-`endDate`, את התקציב ל-`budget`, ואת ערכת הצבע ל-`settings.theme`. המפתחות הישנים לא נמחקים.
- **1 (שלב 2):** המבנה שמתואר כאן.


## גרסת נתונים 2 (שלב 4, אפליקציה 0.4.0)
כל סכום הוא מספר שלם ביחידה הקטנה (אגורה או סטנג).

### `budget`
| שדה | סוג | הערות |
|-----|-----|-------|
| `currency` | מחרוזת | `"ILS"`. בסכום שהוזן בבית יכול להיות גם `"THB"` או `"USD"` |
| `totalMinor` | מספר שלם או `null` | הסכום הכולל שהוזן בבית. משמש רק כשאין חלוקה לקטגוריות |
| `categoriesMinor` | אובייקט | סכום לכל קטגוריה, כולל `emergency`, שנפרד מהתקציב השוטף |
| `profileId` | מחרוזת או `null` | הפרופיל שנטען (`saver`, `realistic` או `comfort`) |
| `estimate` | בוליאני | `true` כשהסכומים באו מפרופיל: הערכת תכנון, לא מאומת |

### `expenses[i]`
| שדה | סוג | הערות |
|-----|-----|-------|
| `id` | מחרוזת | |
| `amountMinor`, `currency` | שלם, מחרוזת | הסכום המקורי |
| `rate` | מספר | כמה ₪ שווה יחידה אחת במטבע, ביום ההזנה. לא משתנה כשהשער משתנה |
| `baseMinor` | שלם | הסכום באגורות, לפי `rate` |
| `category` | מחרוזת | אחת מ-9 הקטגוריות |
| `date` | `"YYYY-MM-DD"` | |
| `destinationId` | מחרוזת או `null` | תחנה מהמסלול |
| `description`, `note` | מחרוזת | עד 80 ועד 140 תווים |
| `method` | `cash`, `card`, `transfer` או `other` | |
| `status` | `paid`, `planned` או `committed` | |

### המרה 1 ל-2
`budget: { amount, currency }` הופך ל-`{ currency, totalMinor: round(amount*100), categoriesMinor: {}, profileId: null, estimate: false }`. שדות לא מוכרים נשמרים. גם קובץ גיבוי מגרסה 1 עובר את אותה המרה.

### חלוקת הוצאות (0.4.1, שדות אופציונליים, בלי שינוי בגרסת הנתונים)
- `trip.people`: מערך של `{ id, name }`. כשהשדה חסר, נחשב כמערך ריק.
- בהוצאה: `paidBy` (מזהה של אדם) ו-`sharedBy` (מערך מזהים). הם קיימים רק כשההוצאה מחולקת.
- **מה נספר:** רק הוצאות בסטטוס `paid`, שכל האנשים בהן קיימים ברשימה. הוצאה עם אדם שהוסר לא נספרת, ולא נמחקת.
